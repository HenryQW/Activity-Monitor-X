# Requirements

What must be true now. Where this file and the spec differ, this file wins: it holds the changes made after the spec.

- **This file:** what. Edit a line in place when a requirement changes; never keep a replaced line.
- **Decision log** (`docs/decisions/`): why, with the options. Append only. Each line here names its D-number.
- **ADRs** (`docs/adr/`): why, for the few choices that are hard to reverse.

Rules:

- Read this file before a UI change. Do not break a line without the user's approval.
- Add or edit the line in the same commit as the change.
- IDs are stable: a new line takes the next free number in its area; a removed line's ID is not used again.
- "(user)" marks a requirement the user asked for or picked.

## WIN: Window and toolbar

- **WIN-1** (user) The window never resizes itself, for the inspector or the toolbar (D21).
- **WIN-2** (user) The sidebar button comes directly after the window buttons (D35).
- **WIN-3** (user) Search is a magnifier at the end of the toolbar; a click or ⌘F opens the system field. An empty field closes back to the magnifier when it loses focus (Escape, a click elsewhere); a query keeps it open (D36, D41, D58).
- **WIN-4** (user) The toolbar has no background: content runs under it with the scroll edge effect; a glass title pill at the leading side shows the screen's icon, title (at most 240 pt, truncated) and subtitle, icon only below 700 pt of detail; item groups are system glass capsules at the trailing edge (D66).
- **WIN-5** (user) Live is one round, icon-only glass button in the toolbar, before the item capsules, on the screens with a range bar: play when paused (regular glass), pause while Live runs (accent-tinted, never red or yellow); label Live with value On or Off; ⌘L. It starts Live; Live again, or ⌘L, returns to the range before Live; a segment shows that range (D48, D58, D66).
- **WIN-6** (user) Start Live and Pause Live do not reload the screen: the chart fades over when Live data is ready (D51).
- **WIN-7** (user) The range bar has 1H, 24H, 7D, 30D, 90D, the shown window as short text, and Custom…, a popover with From/To pickers and Apply. The short text: "Since 8:50 PM" (1H, 24H today), "Since yesterday, 8:50 PM", "Since 16 Oct" (7D and longer); a custom window as an interval with shared parts left out ("22 to 23 Oct"); a custom window inside one day that is not today names the day ("20 Oct, 3:40 to 4:40 PM"); "Live" while Live runs. - **WIN-8** (user) Search and the Inspector button are on every screen and work on what the screen lists (D50).
- **WIN-9** (user) Every icon and button has a hover hint (D26).
- **WIN-10** (user) No toolbar item goes into the overflow: Metric shows its segments while the detail width fits the title pill, the segments and the item capsules (measured, 16 pt hysteresis), else a pop-up that names the metric (D21, D48, D58, D66).
- **WIN-11** (user) Apps, pinned apps, groups and Disk Activity have the range bar as a floating glass capsule at the top of the content column, as wide as its content; Calendar, Alerts and the other System screens do not. The time range is not in the toolbar. As the column narrows, the window text goes first, then the segments become a pop-up. The Calendar bar fits any column width the same way: Show becomes an icon, then the period a pop-up, then the pop-ups lose their indicator; ‹ Today › stays whole; nothing is clipped (D58, D66).
- **WIN-12** (user) The toolbar groups its items into capsules; Quit and Inspector are in the action capsule (WIN-21); the other view options are in a More menu (D60, D73).
- **WIN-13** (user) Every screen has one floating glass footer across the content column (`ScreenFooter`), one borderless strip: first one visual that is the screen's own, then each figure as its value over its label in equal columns across the strip; narrower, the figures alone, then two rows; the content scrolls under it. Apps: the system's trend of the metric, then the values of the metric now and in the range that the table does not give (no busiest app, no peak); totals from bucket means read "About". Calendar: the page's cells as a heat grid, then the mean, the busiest bucket, the top app and its share, and the alert counts. Alerts: the last 7 days as bars by severity, then today's count, the 7 days' critical and warning counts and the most frequent subject. Disk: the startup disk's chips filled to its use, then its free space, read and write now and SMART health. Hardware: each CPU core filled to its use, then uptime, thermal state, and CPU, GPU and memory now. Disk Space: in its own row under the treemap and table (their AppKit panes take no safe area), the shown folder as a small treemap, then its size, items, largest item and share of the volume's used space (of the scan for a folder); the path bar no longer repeats the size and items (SP1). Energy: see SCR-22 (D60, D66, D76, D84, FT2).
- **WIN-14** (user) Hover hints and action labels say the action and the result where space permits (D60).
- **WIN-15** (user) Every chart screen (Apps, pinned apps, groups, Disk Activity) has a vertical glass zoom pill on the chart's trailing edge: Zoom In above Zoom Out, 32 pt hit areas. Zoom In makes the selected span the range, or with no span the next narrower range (90D, 30D, 7D, 24H, 1H) around the shown window; Zoom Out the next wider range. A button that cannot act (1H, 90D, Live) is disabled, not hidden. Hints name the result ("Zoom in to 24 hours around 22 Oct"). Show Whole Range, a small text button after "Ranked for" under the chart, clears the span; Escape does too (D77). View > Zoom In (⌘]) and Zoom Out (⌘[) act on the chart; the subtitle names the view filter. A zoom whose window ends now returns to the quick range (its segment checked, following the clock) (D60, D66).
- **WIN-16** (user) Every menu item uses a system SF Symbol when one represents it accurately, none when no symbol fits; toggles have a symbol and their checkmark; Pin and Unpin are `pin` and `pin.slash` everywhere. A pinned app row has a right-click menu with icons (Show in Inspector, Show in Finder, Colour, Alert Rules…, Unpin App from Sidebar, Quit…) and on hover a pin.slash button that unpins at once (D63, D66).
- **WIN-17** (user) One window background; the inspector is a floating glass panel inset 8 pt with 16 pt corners, starting 8 pt below the toolbar row (the sidebar is the system's). - **WIN-18** (user) The one primary action of a screen is prominent: the toolbar Live button while Live runs (accent-tinted glass, never red or yellow), and an empty state's single action (D66).
- **WIN-19** (user) Hover hints show after the pointer rests 1 s (the app's own tooltip delay, never a system setting); a sidebar row whose name can truncate has a hint with the full name (D66).
- **WIN-20** (user) A pinned app shows its bundle's display name; the executable name or bundle ID shows only when no bundle names it (D66).
- **WIN-21** (user) The toolbar's trailing buttons are one compact capsule of icon buttons in a system control group: Quit (screens with an app inspector), Inspector (`sidebar.trailing`, the symbol of every inspector item), More, Search, each with its name as hint and accessibility label. Live keeps its own round capsule before it; the title pill stays (D73).

## CAL: Calendar and time zone

- **CAL-1** (user) The grid is gapless with hairline separators and square cells; no week number at the left of a row; the Week cell at the right stays. A 1.5 pt stepped line in a quiet system colour marks where the month changes; the first of a month names its month ("1 Oct") (D63).
- **CAL-2** (user) Today has a neutral fill, weekends a lighter neutral tint (never an app colour) with weekday headers in the same secondary text as the others; today wins on a weekend (D63, D87).

## BLD: Build and platform

- **BLD-1** (user) Build, sign and install run without prompts (D52).
- **BLD-2** Scroll bars are stock and follow the system "Show scroll bars" setting, except the inspector panel, whose scroll bars are always overlay (INS-2) (D54, D66).
- **BLD-3** (user) Root never runs code from the user-writable app bundle. The install script, the cask and `make install` copy `amxd` to `/Library/PrivilegedHelperTools` (root:wheel, as is each folder above it; not `/usr/local`, which can belong to the user), check the signature of the root-owned copy, write the LaunchDaemon plist from their own text, and restart the helper; the app does not register the helper. When the helper does not run or is out of date, Settings > Helper shows the install line (D92).
- **BLD-4** (user) Local builds sign with "Activity Monitor X Local Signing" (`make cert`); releases sign in CI with a second self-signed identity, "Activity Monitor X Release Signing", from the secrets `RELEASE_CERT_P12` and `RELEASE_CERT_PASSWORD` in a temporary keychain. `Scripts/make-release-cert.sh` makes that identity (D91).
- **BLD-5** (user) `VERSION` holds the version: `make app` writes it into the bundle as `CFBundleShortVersionString` and `CFBundleVersion`, and `AMX.version` (what `amx mcp` reports) must equal it (D91).
- **BLD-6** (user) A tag `v<VERSION>` runs the release workflow on the `xcode-27` runner: test, build, `make dmg`, a check that the app and `amxd` have the certificate that `CERT` in `website/public/install.sh` names, then a GitHub release with `AMX-<version>.dmg`, its `.sha256` and `AMX.dmg`, and, with `TAP_TOKEN`, the `amx` cask in HenryQW/homebrew-tap with that certificate (D91, D92).
- **BLD-7** (user) `curl -fsSL https://amx.henry.wang/install.sh | sh` installs the latest release, as for the other HenryQW apps: it accepts only an app, `amxd` and `amx` with their identifiers and the release certificate (SHA-1 pin), copies the app to `/Applications`, installs the helper as BLD-3 says with one sudo prompt, and opens the app. The home page shows this line; the disk image has "Read me first.txt" with it (D92).
- **BLD-8** (user) The logo is the app icon's chip as line art with the two app colours on its die: `website/public/logo.svg` (`currentColor`) in the site header with the word "AMX" and in the Open Graph cards; `icon.svg` (dark lines) and `icon-dark.svg` (light lines) as the favicon and in the README header. The home page hero keeps the app icon (D94).
